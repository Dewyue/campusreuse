设计定位：无自营库存的校内二手撮合服务，以公共地点面交、知情选择和再使用记录为核心。平台名称不代表学校官方认证。课题由校园二手市场收敛而来，餐盒方案不再作为当前主线；不依赖外包食堂运营配合。

## 设计原则落地

- 状态可见：请求、接受、交接、完成分开，不把一次点击称为成交。
- 防错：不允许预约自己的物品；卖家接受一份请求后锁定单件库存，其他请求结束；拒绝过去时间。
- 知情选择：发布必须有照片、品相、功能、已知瑕疵、校区与可面交安排。
- 用户可控：双方确认前可取消；拒绝、取消、过期都不计完成；不自动扣款或收预约金。
- 如实表达：消息入口改为面交，不假装存在聊天；未认证、样例商品和未核算状态明确标识。
- 最小个人信息：面交填写公共地点，不要求宿舍房号、证件照片或公开手机号。身份认证仍需另行设计。

## 当前服务流程

卖家发布 -> 买家核对并提出时间地点 -> 卖家接受 -> 当面验货及协商 -> 双方分别确认交接 -> 买家填写再使用记录。

| 状态 | 行为与库存 |
| --- | --- |
| pending | 等待卖家；允许其他人提出请求 |
| accepted | 卖家接受；单件物品不再接受新请求 |
| completed | 双方均确认；退出可预约列表；仍保留历史记录 |
| cancelled / declined / expired | 不计完成；没有其他有效约定时释放库存 |
| disputed | 暂停后续预约，不计完成；尚无客服仲裁与恢复流程 |
| legacy | 迁移旧版意向，不伪装成已约定时间地点的面交 |

默认请求在建议时间已过时过期；已接受且双方均未确认的约定，在建议时间后 24 小时过期。30 天内才能提出预约。以上是可调整的课堂演示规则，不是已验证的校园政策。任意一方确认后不再自动过期或直接取消，以免掩盖交付分歧。

目前不支持在同一记录内议价、改期、撤下/编辑商品或取消后自动恢复其他买家的旧请求。改期需双方均未确认时取消并重新提出；下一阶段应加入双方确认的改期流程。单方确认后长期无响应、争议恢复必须先补充治理机制再开放真实运营。

## 可持续核算

依据 [WBCSD 避免排放指南](https://www.wbcsd.org/resources/guidance-on-avoided-emissions-helping-business-drive-innovations-and-scale-solutions-toward-net-zero/)，应比较一致功能单位与服务期限下的参考情景和再使用情景，而不是把二手成交数直接乘以新品制造排放。

概念关系：净避免排放 = 参考情景生命周期排放 - 再使用情景生命周期排放。

完成记录先采集：没有此次交易会买新品、其他二手、不买还是不确定；主要出行方式；额外往返里程；预计继续使用月数。问卷是自报证据，不能直接当作真实替代率或物品寿命。还需要卖方额外出行、清洁维修、配送、使用能耗差异、剩余寿命、废弃处理及排放因子的可靠数据，并说明分配方法、系统边界和不确定性。数值可能为负，不应强制显示“节省”。

同一笔交易只按独立记录计一次，买卖双方的个人展示不可相加。预约、取消、单方确认、样例数据及有分歧记录均不得当作课程的实际减排成果。当前 carbonStatus 为 not_calculated，没有伪造 kgCO2e。

建议先选书籍和低风险生活用品做小样本试点，限制品类与功能单位后再核算。数码产品应补充电池、维修和能效信息，不宜直接套一个通用品类系数。

## 真实校园验证与上线前置条件

以下都是待验证假设，而非访谈结论：同校区比全校更方便；毕业季与开学季需求不同；爽约和瑕疵争议是主要障碍。建议访谈近期买卖双方，记录交易路径、校区、放弃原因、可接受时间、信任来源，观察一次真实面交。测试能否看懂“等待卖家”和“双方完成”的区别，以及填写瑕疵和问卷的负担。

先补真实身份与会话安全、举报审核、隐私处理、请求频率限制、图片存储与审核、商品撤下、通知、改期、争议恢复，再考虑公开运行。不能假定学校会提供统一身份接口、固定面交站或工作人员。现有 X-Demo-Session 可由客户端提供，不是登录认证，不得裸露到公网。

在线预览数据仅存在本浏览器，样例卖家不会响应。独立后端支持不同演示会话交互，并已用隔离数据库的两浏览器流程测试；这不代表伙伴服务器已部署、真实学生已使用或校园身份已经验证。
